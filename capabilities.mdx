The SDK is organized into capability groups. Cobalt grants only the capabilities registered for your game and allowed by the player.

<Warning>
  This page describes the intended product surface. Individual capabilities may ship in different SDK releases.
</Warning>

## Player-aware experiences

<CardGroup cols={2}>
  <Card title="Public player identity" icon="user" href="/features/player">
    Read the player's Cobalt ID, display name, username, and avatar.
  </Card>
  <Card title="Connection events" icon="plug" href="/concepts/connection-model">
    React when the launcher, account, network, or permissions change.

</CardGroup>

Use public identity for attribution and Cobalt-specific UI. Never use it as a substitute for your own game account unless you implement an explicit account-linking flow.

## Storage

<Card title="Cloud saves" icon="cloud" href="/features/cloud-saves">
  Synchronize declared save locations, request checkpoints, and resolve conflicts without exposing Cobalt credentials.
</Card>

Your game keeps ownership of its save format. Cobalt handles transport, version tracking, quotas, and recovery.

## Game installation

<CardGroup cols={2}>
  <Card title=".clgame packages" icon="package" href="/distribution/clgame">
    Install game data without requiring an official SDK integration.
  </Card>
  <Card title="Install links" icon="link" href="/distribution/install-links">
    Open Cobalt for an official ID or an encoded HTTPS package URL.
  </Card>
</CardGroup>

Official `c_` games can later use signed releases, repair, update channels, and direct installation. Public sandbox projects cannot distribute files. Unofficial `.clgame` packages remain a separate, clearly labeled installation path and cannot claim official status through local metadata.

## Capabilities intentionally excluded

The game SDK does not expose:

- Cobalt account or refresh tokens
- The launcher's raw Electron IPC
- Arbitrary filesystem access through Cobalt
- Friend messages or private social history
- Unrestricted network proxying
- Silent installs or elevation
- Arbitrary commands from `.clgame` packages

These boundaries keep a compromised game process from becoming a privileged Cobalt client.
