---
title: ".clgame packages"
description: "Package installable game data without requiring an official SDK integration."
---

A `.clgame` file describes an installable game. It can contain the payload itself or reference HTTPS-hosted files. A game does not need an official Cobalt SDK integration to use this format.

An independent `.clgame` package is not Cobalt distribution for an `s_` project. Sandbox projects cannot publish releases, updates, or install routes under their sandbox ID. Opening a local or remote community package uses a separate unverified-package flow.

<Warning>
  This page proposes the `.clgame` format. Treat the schema as an example until the installer specification is finalized.
</Warning>

## Package layout

A `.clgame` file is a constrained archive:

```text
sunken-city.clgame
├── manifest.json
├── assets/
│   ├── icon.png
│   └── hero.webp
├── payload/          optional embedded game files
└── signature.json    optional for community packages
```

Cobalt does not execute installer scripts from the archive. Packages cannot request arbitrary commands, elevation, registry changes, or writes outside their selected installation directory.

## Example embedded manifest

```json
{
  "schemaVersion": 1,
  "game": {
    "name": "The Sunken City",
    "developer": "Example Studio"
  },
  "release": {
    "version": "1.0.0",
    "platform": "windows",
    "architecture": "x64"
  },
  "payload": {
    "type": "embedded",
    "root": "payload"
  },
  "launch": {
    "executable": "SunkenCity.exe",
    "arguments": []
  }
}
```

## Example remote manifest

```json
{
  "schemaVersion": 1,
  "game": {
    "name": "The Sunken City",
    "developer": "Example Studio"
  },
  "release": {
    "version": "1.0.0",
    "platform": "linux",
    "architecture": "x64"
  },
  "payload": {
    "type": "remote",
    "files": [
      {
        "url": "https://downloads.example.com/game.tar.zst",
        "sizeBytes": 2147483648,
        "sha256": "0123456789abcdef..."
      }
    ]
  },
  "launch": {
    "executable": "SunkenCity",
    "arguments": []
  }
}
```

Cobalt downloads every remote file into staging and verifies it before modifying an existing installation.

## Package identity

An unofficial package receives an `l_` library identity unless Cobalt independently matches it to an official catalog game. Claiming an `s_` or `c_` ID in `manifest.json` does not bind the package to that project or make it official.

Official packages are bound to trusted release metadata and require a publisher signature. Community signatures can identify repeat releases from the same author, but Cobalt must label them as unverified.

## Installation flow

<Steps>
  <Step title="Inspect">
    Cobalt parses the manifest, rejects unsafe archive paths, and calculates the expanded size.
  </Step>
  <Step title="Confirm">
    The player reviews the source, signature status, platform, version, size, and install location.
  </Step>
  <Step title="Stage">
    Cobalt extracts or downloads files into a new staging directory.
  </Step>
  <Step title="Verify">
    Cobalt verifies declared sizes, hashes, signatures, and the launch executable.
  </Step>
  <Step title="Install">
    Cobalt moves the staged build into place atomically and records every managed file.
  </Step>
</Steps>

See [Install links](/distribution/install-links) to open a remote package from a website.
